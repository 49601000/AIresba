# AIレスバ v1.5 仕様書 — Claude退場理由ネタ在庫管理

- 状態：**仕様案（実装未着手）**
- 作成：2026-10-28
- 対象：`49601000/AIresba`
- 参照基準：main `c761b15d94792c9a0be0ce191665db481a10850b`
- 共通開発規約：https://github.com/49601000/development-standard/blob/main/AGENTS.md
- 目的：Claudeの「高貴で不条理な退場理由」のマンネリ防止。4人のレスバ演出そのものは変えない。

## 1. 背景・目標

現行v1.4はClaudeの門限・退場理由を `styles/nanj.json` の `character_specific_rules.claude_curfew_mode` で生成指示している。毎回の生成に任せると退場理由の発想が似通うため、別途Geminiが考えた大量の候補を在庫化し、UIで選んで完成プロンプトに注入する。

**成功条件**：ユーザーが未使用の理由を選択して生成できること、使用した理由が同じブラウザで再使用候補にならないこと、後日のバッチでDrive/Sheets側へ使用情報を反映できること。理由は豊富なので、コピー失敗や保存漏れをゼロにする厳密なトランザクションは要求しない。

## 2. 境界と責務

| 要素 | 責務 |
|---|---|
| Gemini（別口で利用） | 退場理由の候補を複数件生成。原稿本文は生成しない |
| JSON化ツール（新規） | Gemini出力を規定JSONへ整形、ID付与、最低限の形式・重複確認をしてDrive投入用ファイルを出力 |
| Google Drive | 新規ネタJSON・使用済みJSONの**原本保管場所（データ基盤）** |
| Google Sheets | GASが管理する索引・在庫台帳（ID、本文、使用状態、取込日時など） |
| GAS（新規） | 一日一回、Driveの新規ネタJSONと使用済みJSONを取込み、Sheets台帳を更新。UIへの読取データを生成・公開 |
| AIresba UI（GitHub Pages） | 未使用ネタのプルダウン選択、選択理由を完成プロンプトに注入、コピー時のローカル使用履歴記録、独立した「使用履歴JSON保存」 |

GitHub PagesからDrive/Sheetsへ直接書き込まない。通常操作にGoogleログインを要求しない。GASによる公開読取データは**退場理由と不透明なID等の公開可能な情報のみ**とし、台帳の管理用情報や個人情報を公開しない。

## 3. データフロー

1. 利用者が別口のGeminiで「高貴・不条理・具体的・無駄に大掛かり」な退場理由案を複数生成する。
2. JSON化ツールで各案を正規化・ID付与し、**新規ネタJSON**を出力する。利用者がDrive指定フォルダへ配置する。
3. GAS日次バッチがDrive内の新規ネタJSONと使用済みJSONを読み、SheetsをID単位でupsertする。処理済みファイルが再登場しても重複登録・重複カウントしない。
4. GASは未使用の理由一覧をUIが読み込めるJSONとして提供する（方式は第9節）。
5. AIresba UIは候補をプルダウンに表示。利用者が任意で1件選び、既存のGenerate Promptでプロンプトに注入する。
6. 利用者が**Copy**を押したら、その完成プロンプトで使用された候補IDをブラウザのlocalStorageへ記録する。保存済みIDは同じブラウザの候補から即時除外・選択不可にする。同じプロンプトのCopy繰り返しは重複記録しない。
7. UIに既存のGenerate/Copyとは別の「使用履歴JSON保存」ボタンを設ける。押すとローカルの未出力の使用IDをJSONとして**端末へダウンロード**する。Google Driveへのアップロードはユーザーが行う。
8. 次の日次バッチでGASが使用履歴JSONを読み、該当IDを使用済みに更新する。次の読取データから除外する。

**重要**：「JSON保存」ボタンだけでDriveにアップロードされたことにはならない。手動Driveアップロードが完了して初めてバッチ側が認識する。

## 4. JSON仕様（実装時の初期提案）

### 新規ネタ（Drive原本）
```json
{
  "schema_version": 1,
  "type": "claude_exit_ideas",
  "items": [
    {
      "id": "ce_000001",
      "text": "我が家のペルシャ猫がダイソンのドライヤー5台同時照射を要求している"
    }
  ]
}
```
- `id` は永続的で一意。新規生成時に衝突しない設計とする（例の連番は説明用。実装では一意性を保証する方式を選ぶ）。
- `text` は一つの退場理由として単独で使える短文。キャラの発言全体、解説、イメージ図、他の出演者の台詞は保存しない。
- 同一IDの再取込は重複登録しない。類似文の完全自動排除は必須ではないが、少なくとも完全一致は検出する。

### 使用履歴（ブラウザから書き出し、Driveへ手動配置）
```json
{
  "schema_version": 1,
  "type": "claude_exit_usage",
  "exported_at": "2026-10-28T14:00:00+09:00",
  "used_ids": ["ce_000001", "ce_000002"]
}
```
- 一度のエクスポートで複数IDを含む。日付ごとの生成ファイル名は識別しやすい形式にする。
- GASは `used_ids` を集合として処理し、重複を無害化する。
- 未知のIDは勝手に新規ネタとして登録せず、取込ログで確認できるようにする。

このJSONは**論理スキーマの初期案**。ファイル名、ID生成方法、Driveフォルダ構成は実装時に最小構成で確定し、仕様へ反映する。

## 5. UI・操作

- 既存UIに「Claude退場理由」プルダウンを追加する。**選択は任意**で、未選択は従来どおり自動生成。
- 表示候補は未使用のみ。通信に失敗した場合も従来のプロンプト生成は使える。
- Generate Prompt時に選択IDとその退場理由を完成プロンプトへ含める。**Claudeの退場イベントが起きた場合に限り、その理由として使う**。理由を選択しただけで退場自体を強制しない。
- 生成したプロンプトの「使用ネタID」を出力と結びつけて保存する。別の候補を選択しただけでは使用扱いにしない。
- Copy時に選択理由をローカル使用済みに登録する。ユーザーはコピーに成功したか否かを厳密管理しない方針（コピー失敗時のネタ消費は許容）。生成のみでは使用済みにしない。
- ボタンを独立して「使用履歴JSON保存」とし、未出力件数を表示する。通常のCopyボタンの挙動を妨げない。
- ローカル履歴は**JSONを書き出した後も消さず**、`exported` 管理などで次回出力対象から除外する。同じブラウザでは使用済みIDを選択不可にする。
- 別端末・別ブラウザでは日次同期まで既使用IDが見える可能性を許容する。
- 保存処理の失敗や未アップロード時の取りこぼしは許容するが、UIで「ダウンロード＝Driveへの保存済み」と誤認させない。

## 6. 既存演出との整合

- 現行 `claude_curfew_mode` の発動条件・退出の所作・他3人のツッコミは維持。
- `patches/claude_walkout_event.json` は既存どおり。選択した理由は**退場理由の内容だけ**を置換・指定する。
- GPT/Grok/Geminiの人格、1D20ルール、Opening、Length、Patch、組版、コピーなどの既存機能は変更しない（必要な最小限の接続修正を除く）。
- 外部候補が未取得・未選択の場合は完全に従来動作へ戻る。
- 文章中に他人の実在情報・センシティブな個人データは入れず、架空の不条理ネタとして扱う。

## 7. GAS日次運用

- 1日1回の時間主導トリガーで、指定Driveフォルダから新規ネタと使用済みファイルを取得し更新する。
- JSON原本は消去せず保持。台帳はIDベースの最新状態を示し、取込済みファイル識別子等で冪等に処理する。
- バッチは `UNUSED` / `USED` を管理。未知ID・不正JSON・一意性衝突等はログに残し、既存の良好データを壊さない。
- 細かな失敗時通知や大規模な監視は初期スコープ外。
- 入手済みのJSONを毎日再読みしても、同一IDによって使用状態が `UNUSED` に戻ることがあってはならない。

## 8. 採用時の受入条件

1. 新規ネタJSONをDrive投入→GAS日次バッチ→Sheets未使用台帳→UIプルダウンに反映される。
2. 選択理由が完成プロンプトに入るが、Claude退場の発動自体は強制しない。
3. Copyで使用IDをlocalStorage記録し、同じブラウザですぐ再利用できなくなる。
4. 「使用履歴JSON保存」でファイルがダウンロードされ、Driveへの**手動アップロード**後、次回GAS実行でUSEDになる。
5. JSONの重複取込・同じプロンプトの再Copyで使用状況が不正化しない。
6. GAS・ネットワーク不調時も従来のAIレスバが使える。
7. v1.4に戻せる復元ポイントを用意し、既存公開版はv1.5の採用判断までは変えない。

## 9. 実装時に確定する小さな設計事項

- **読取経路**：GASの読取専用Webエンドポイント、またはGASが日次生成する公開用JSON（静的配信）を比較して選ぶ。GitHub Pagesからブラウザが取得できるようCORS/公開権限を検証する。Sheetsの非公開台帳を直接フロントに渡さない。
- **Drive受け渡し**：新規ネタJSON・使用履歴JSONをどのフォルダへ手動投入するか、運用しやすい命名を決める。
- **JSON化ツールの形態**：Geminiの貼り付け本文からJSONをダウンロードする小さな独立UIを第一候補とする。Gemini APIによる自動生成は要求しない。
- **発動条件との関係**：現行のClaude門限仕様には字数の記述に揺れがあるが、今回の変更ではその挙動・文言を勝手に修正しない。
- **端末**：localStorageはブラウザ単位。端末移行時に過去の使用ログは自動同期しない。
